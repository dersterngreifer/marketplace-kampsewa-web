## 1. Endpoint: Detail Profil Toko Publik

- **Method:** `GET`
- **URL:** `/api/store/{id_user}`
- **Auth:** Tidak wajib (Public — dapat diakses tanpa Bearer Token)

**Contoh Response Sukses (200 OK):**
```json
{
  "success": true,
  "data": {
    "id_user": 2,
    "nama_store": "Tenda Adventure Abadi",
    "deskripsi_toko": "Penyewaan alat camping terlengkap di Bandung",
    "foto_toko": "https://domain.com/assets/image/customers/logo_toko/tenda_abadi.png",
    "banner_toko": "https://domain.com/assets/image/customers/banner/banner.jpg",
    "rating_toko": 4.8,
    "total_ulasan": 120,
    "total_produk_aktif": 45,
    "total_transaksi_selesai": 350,
    "alamat": {
      "provinsi": "Jawa Barat",
      "kota": "Bandung",
      "detail_alamat": "Jl. Setiabudi No. 12"
    },
    "tanggal_bergabung": "2025-01-10T00:00:00.000Z"
  }
}
```

**Catatan Implementasi:**
- `rating_toko` dan `total_ulasan` dihitung secara real-time dari tabel `rating_produk` berdasarkan seluruh produk milik toko tersebut.
- `total_produk_aktif` dihitung dari produk yang **memiliki stok > 0 dan harga sewa terdaftar**.
- `total_transaksi_selesai` dihitung dari tabel `penyewaan` yang berstatus `'Selesai'` dan mengandung produk milik toko ini (via join ke `detail_penyewaan` dan `produk`).
- `foto_toko` mengembalikan URL placeholder jika toko belum mengunggah foto.
- `banner_toko` bernilai `null` jika belum di-upload.
- `alamat` akan bernilai `null` jika toko belum mengisi lokasi toko.

**Response Error:**
```json
// 404 – Toko tidak ditemukan
{ "success": false, "message": "Toko tidak ditemukan." }

// 404 – User ada tapi belum buka toko
{ "success": false, "message": "User ini belum membuka toko." }
```

## 2. Endpoint: List Produk Toko Publik (dengan Filter)

- **Method:** `GET`
- **URL:** `/api/store/{id_user}/products`
- **Auth:** Tidak wajib (Public — namun `is_liked` hanya akurat jika Bearer Token disertakan)
- **Query Params (Opsional):**
  - `kategori` — filter produk berdasarkan nama kategori (contoh: `?kategori=Tenda`)
  - `search` — pencarian nama/deskripsi produk dalam toko (contoh: `?search=eiger`)
  - Kedua param bisa digabungkan: `?kategori=Tenda&search=eiger`

**Contoh Response Sukses (200 OK):**
```json
{
  "success": true,
  "data": [
    {
      "id_produk": 15,
      "nama_produk": "Tenda Eiger 4 Orang",
      "kategori": "Tenda",
      "harga_sewa": 50000,
      "rating": 4.5,
      "total_disewa": 12,
      "total_likes": 30,
      "is_liked": false,
      "foto_depan": "https://domain.com/assets/image/customers/produk/...",
      "images": ["https://..."],
      "foto_array": [{ "id": 1, "url": "https://...", "urutan": 1, "tipe_sumber": "internal" }],
      "foto_toko": "https://domain.com/assets/image/customers/logo_toko/...",
      "nama_toko": "Tenda Adventure Abadi",
      "stok": 5
    }
  ]
}
```

**Catatan Implementasi:**
- Field `is_liked` bernilai `false` jika request tanpa Bearer Token (guest). Jika token disertakan, nilai ini akurat sesuai status like user tersebut.
- Produk diurutkan berdasarkan `created_at DESC` (terbaru tampil pertama).
- Filter `kategori` dan `search` bersifat case-insensitive (`LIKE %value%`).

**Response Error:**
```json
// 404 – Toko tidak ditemukan atau belum buka toko
{ "success": false, "message": "Toko tidak ditemukan." }
```

## Ringkasan Teknis

```
Route: GET /api/store/{id_user}             → StoreController@showStoreProfile
Route: GET /api/store/{id_user}/products    → StoreController@showStoreProducts
```

Kedua route didaftarkan di luar blok `middleware('auth:sanctum')` sehingga **dapat diakses secara publik** tanpa token. Bearer Token tetap dapat disertakan secara opsional untuk mendapatkan nilai `is_liked` yang akurat pada list produk.
