## 1. Latar Belakang & Analisis Kebutuhan

Saat ini, fitur iklan dan katalog produk pada platform KampSewa memiliki beberapa keterbatasan operasional:
1. **Banner Iklan Masih Statis & Tidak Terhubung ke Toko Mitra:**
   - Iklan banner di Dashboard belum memiliki relasi data langsung ke mitra toko (`id_user` pemilik toko) atau ke produk tertentu (`id_produk`).
   - Tombol *"Belanja Sekarang"* saat ini hanya mengarahkan pengguna ke katalog umum (halaman produk index 1), belum mengarahkan ke toko mitra yang memasang iklan tersebut.
2. **Belum Tersedianya Sistem Diskon / Promo Produk:**
   - Belum ada skema data promo di database, backend API, maupun dashboard web mitra.
   - Mitra belum dapat mengadakan program promosi, baik untuk **seluruh produk di tokonya** (misal: *Diskon Pembukaan Toko 15% untuk Semua Alat*) maupun **produk pilihan tertentu** (misal: *Flash Sale Tenda Dome Coleman Diskon 25%*).
   - Desain kartu produk belum memiliki representasi harga coret (*strikethrough original price*) dan label persentase diskon (*discount badge*).

Dokumen ini disusun sebagai usulan rancangan komprehensif bagi **Tim Backend dan Web Admin** agar sistem promosi iklan dan diskon produk dapat diimplementasikan secara terstruktur, konsisten, dan terintegrasi penuh dengan aplikasi mobile Flutter.

## 2. Arsitektur Konsep Iklan Mitra (Promosi & Campaign)

Ketika mitra memasang iklan banner di aplikasi, terdapat **2 skenario utama**:

```
                              ┌──────────────────────────────────────────────┐
                              │           IKLAN MITRA (DASHBOARD)            │
                              └──────────────────────┬───────────────────────┘
                                                     │

                         ▼                                                       ▼
            ┌──────────────────────────┐                           ┌──────────────────────────┐

            │   (Branding Toko/Katalog)│                           │ (Campaign Harga Diskon)  │
            └────────────┬─────────────┘                           └────────────┬─────────────┘
                         │                                                      │
                         │                                          ┌───────────┴───────────┐
                         │                                          ▼                       ▼
                         │                               ┌─────────────────────┐ ┌─────────────────────┐
                         │                               │ A. Diskon Semua Item│ │ B. Diskon Item Pilih│

                         │                                          │                       │

                         │                                          │                       │
                         ▼                                          ▼                       ▼
               Profil Toko Publik                       Profil Toko Publik         Detail Produk Terkait /
             (LayoutPublicStoreProfile)              + Banner Notifikasi Promo     Profil Toko Filter Promo
```

### Skenario 1: Iklan Toko Reguler (Store Awareness)
- **Tujuan**: Memperkenalkan toko mitra dan katalog peralatan campingnya kepada pengguna luas.
- **Aksi Tap**: Tombol *"Belanja Sekarang"* atau banner langsung mengarahkan pengguna ke halaman **Profil Toko Publik Mitra** (`LayoutPublicStoreProfile`) menggunakan `id_user` mitra.
- **Tampilan**: Toko publik menampilkan profil lengkap mitra, reputasi/rating toko, lokasi, dan daftar seluruh peralatan yang disewakan.

### Skenario 2: Iklan Promo Diskon (Diskon Semua Produk atau Produk Tertentu)
- **Tipe A (Diskon Semua Produk Toko / Store-Wide Promo)**:
  - Contoh: *"Spesial Weekend: Diskon 20% Semua Tenda & Peralatan di Toko CampOutdoor"*.
  - **Aksi Tap**: Mengarahkan ke `LayoutPublicStoreProfile` milik mitra.
  - **Di Halaman Toko**: Muncul **Banner Pemberitahuan Promo Aktif** di bagian atas profil toko, dan seluruh kartu produk menampilkan harga asli dicoret serta harga sewa promo.
- **Tipe B (Diskon Produk Tertentu / Featured Item Promo)**:
  - Contoh: *"Promo Spesial: Tenda Dome Coleman 4P Diskon 30% /hari"*.
  - **Aksi Tap**: Mengarahkan langsung ke halaman **Detail Produk** (`LayoutDetailProduct`) dari produk tersebut, atau ke profil toko dengan tab/filter *"Sedang Promo"*.

## 4. Usulan Skema Database (Database Schema Proposal)

### 1. Penyesuaian Tabel Iklan (`iklan`)
Menambahkan kolom relasi agar iklan dapat menautkan toko mitra atau produk spesifik:
```sql
ALTER TABLE iklan ADD COLUMN id_user INT NULL;            -- ID Mitra Toko pemilik iklan
ALTER TABLE iklan ADD COLUMN id_produk INT NULL;          -- ID Produk spesifik (opsional)
ALTER TABLE iklan ADD COLUMN target_type VARCHAR(20) DEFAULT 'store'; -- 'store', 'product', 'external'
ALTER TABLE iklan ADD COLUMN badge_promo VARCHAR(50) NULL;-- Misal: "Diskon 20%", "Flash Sale"
ALTER TABLE iklan ADD COLUMN tanggal_mulai DATETIME NULL;
ALTER TABLE iklan ADD COLUMN tanggal_selesai DATETIME NULL;
ALTER TABLE iklan ADD COLUMN status ENUM('active', 'inactive', 'expired') DEFAULT 'active';
```

### 2. Tabel Baru: Promosi Toko (`promosi_toko`)
Tabel untuk menampung program diskon yang dibuat oleh mitra:
```sql
CREATE TABLE promosi_toko (
    id_promo INT AUTO_INCREMENT PRIMARY KEY,
    id_user INT NOT NULL,                                  -- ID Mitra Toko
    judul_promo VARCHAR(150) NOT NULL,                     -- Misal: "Promo Akhir Tahun"
    deskripsi_promo TEXT NULL,                             -- Penjelasan detail promo
    tipe_diskon ENUM('persen', 'nominal') DEFAULT 'persen',-- Persentase (%) atau potongan tetap (Rp)
    nilai_diskon DECIMAL(10,2) NOT NULL,                   -- Contoh: 20 (untuk 20%) atau 15000 (untuk Rp 15.000)
    cakupan ENUM('all_products', 'selected_products') DEFAULT 'all_products', -- Semua produk atau produk tertentu
    tanggal_mulai DATETIME NOT NULL,
    tanggal_selesai DATETIME NOT NULL,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (id_user) REFERENCES users(id) ON DELETE CASCADE
);
```

### 3. Tabel Relasi: Produk Promo (`promosi_produk`)
Digunakan jika cakupan promo adalah `selected_products`:
```sql
CREATE TABLE promosi_produk (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_promo INT NOT NULL,
    id_produk INT NOT NULL,
    FOREIGN KEY (id_promo) REFERENCES promosi_toko(id_promo) ON DELETE CASCADE,
    FOREIGN KEY (id_produk) REFERENCES produk(id) ON DELETE CASCADE,
    UNIQUE KEY unique_promo_produk (id_promo, id_produk)
);
```

## 4. Spesifikasi Filter Khusus Toko Publik Mitra (`LayoutPublicStoreProfile`)

Pada halaman profil publik toko mitra di aplikasi mobile, calon penyewa membutuhkan filter dan sorting agar dapat memilih produk sesuai anggaran dan promo yang tersedia.

### A. Opsi Filter & Sorting yang Wajib Didukung
1. **Promo Terbesar (`discount_desc`)**: Mengurutkan produk dari persentase diskon tertinggi (misal: Diskon 40% -> 30% -> 20%).
2. **Promo Terkecil (`discount_asc`)**: Mengurutkan produk dari persentase diskon terendah yang masih aktif.
3. **Harga Terendah (`price_asc`)**: Mengurutkan produk dari harga sewa promo termurah (setelah dipotong diskon) ke harga tertinggi.
4. **Harga Tertinggi (`price_desc`)**: Mengurutkan produk dari harga sewa tertinggi ke terendah.
5. **Hanya Produk Promo (`is_discount=true`)**: Menyaring hanya produk yang sedang memiliki potongan harga aktif.
6. **Kategori Produk (`category_id` / `category_name`)**: Memfilter berdasarkan kategori (Tenda, Pakaian, Peralatan, Tas & Sepatu, dll.).

### B. Desain Komponen UI Filter pada Mobile
- **Bar Filter & Sorting**: Terletak tepat di bawah informasi banner profil toko dan pencarian produk toko.
- **Tampilan Chips Cepat**:
  - `[Semua]` | `[🔥 Diskon Terbesar]` | `[💲 Harga Terendah]` | `[💲 Harga Tertinggi]`
- **Tombol Modal Filter**: Tombol ikon filter untuk kombinasi filter rentang harga sewa, kategori, dan status promo.

```sql
CREATE TABLE promosi_toko (
    id_promo BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    id_user BIGINT UNSIGNED NOT NULL,
    judul_promo VARCHAR(150) NOT NULL,
    deskripsi_promo TEXT NULL,
    poster VARCHAR(255) NULL,
    tipe_diskon ENUM('persen', 'nominal') DEFAULT 'persen',
    nilai_diskon DECIMAL(10,2) NOT NULL,
    cakupan ENUM('all_products', 'selected_products') DEFAULT 'all_products',

    tanggal_selesai DATETIME NOT NULL,
    is_banner BOOLEAN DEFAULT FALSE,
    is_active BOOLEAN DEFAULT TRUE,
    status ENUM('active', 'draft', 'inactive') DEFAULT 'active',
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    FOREIGN KEY (id_user) REFERENCES users(id) ON DELETE CASCADE
);
```

### C. Tabel Relasi: `promosi_produk`
```sql
CREATE TABLE promosi_produk (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    id_promo BIGINT UNSIGNED NOT NULL,
    id_produk BIGINT UNSIGNED NOT NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    FOREIGN KEY (id_promo) REFERENCES promosi_toko(id_promo) ON DELETE CASCADE,
    FOREIGN KEY (id_produk) REFERENCES produk(id) ON DELETE CASCADE,
```

# Report Perbaikan Fitur Metode Pembayaran / Transfer Toko Mitra (`GET /api/transaksi/bank-toko`)
**Tanggal**: 13-10-2026 (Pembaruan Isolasi Data Rekening Bank Toko Berdasarkan User Login)

---

## 1. Latar Belakang Masalah (Root Cause Analysis)

Pada halaman pendaftaran/pengaturan toko mitra mobile (`LayoutTambahDataToko` dan `LayoutTambahMetodeTransfer`), ditemukan permasalahan daftar metode transfer bank menampilkan banyak sekali rekening bank secara otomatis, padahal user yang sedang login belum memilih atau menambahkan rekening bank miliknya.

Setelah dilakukan penelusuran menyeluruh antara Frontend Mobile Flutter dan Backend Laravel, ditemukan dua penyebab utama:

1. **Bug Query Parameter Dio (Frontend Mobile Flutter)**:
   - Pada method `apiTransaksi.getBankOpsiPembayaran(context, idStr)`, Flutter melakukan HTTP request dengan method `GET`:
     ```dart
     Map body = {'id_user': idToko};
     final response = await dio.get(url, data: body, ...);
     ```
   - Dio mengirim `{'id_user': idToko}` di dalam **HTTP Request Body** (`data: body`), bukan sebagai **URL Query Parameter** (`queryParameters: {'id_user': idToko}`).
   - Protokol HTTP GET standarnya tidak menggunakan message body, sehingga Laravel tidak membaca isi body GET request pada pemanggilan `$request->query('id_user')`. Akibatnya, nilai `$id_user` di sisi backend selalu terbaca `NULL`.

2. **Celah Filter Query pada Controller Backend (`TransaksiController@bankToko`)**:
   - Kode awal pada `TransaksiController.php`:
     ```php
     $id_user = request()->query('id_user');
     $name_store = request()->query('name_store');

     $bank = Bank::select('bank.id', 'bank.id_user', 'bank.rekening', DB::raw('UPPER(bank.bank) as bank'))
         ->where(function ($query) use ($id_user, $name_store) {
             if ($id_user) {
                 $query->where('id_user', $id_user);
             }
             if ($name_store) {
                 $query->orWhere('name_store', $name_store);
             }
         })
         ->get();
     ```
   - Ketika `$id_user` bernilai `null` dan `$name_store` bernilai `null`, blok `where()` di atas tidak memiliki kondisi filter sama sekali!
   - Akibatnya, query yang dieksekusi adalah `SELECT ... FROM bank`, yang mengekstrak **seluruh data rekening bank milik SEMUA pengguna di tabel database** tanpa filter.
   - Selain itu, tabel `bank` tidak memiliki kolom `name_store`, sehingga pemanggilan `orWhere('name_store', ...)` pada tabel `bank` akan menghasilkan error `Column not found` jika `name_store` dikirim.

---

## 2. Solusi & Perbaikan yang Telah Diimplementasikan

### A. Perbaikan Sisi Backend (`marketplace-kampsewa-web`)
1. **Perbaikan Keamanan & Logika Filter (`TransaksiController@bankToko`)**:
   - Mendukung pembacaan parameter dari query string maupun request input: `request()->query('id_user') ?? request()->input('id_user')`.
   - Menambahkan fallback autentikasi token Bearer Sanctum jika `id_user` tidak dikirim: `auth('sanctum')->id()`.
   - **Isolasi Data**: Jika `id_user` dan `name_store` tidak ditemukan, backend **TIDAK AKAN** membuang seluruh isi tabel `bank`, melainkan mengembalikan array kosong `[]`:
     ```php
     if (!$id_user && !$name_store) {
         return response()->json([
             'message' => 'success',
             'bank' => [],
         ]);
     }
     ```
   - Filter `name_store` diperbaiki dengan relasi `whereHas('user', ...)` karena kolom `name_store` berada pada tabel `users`.
2. **Penambahan Relasi pada Model `Bank.php`**:
   - Menambahkan method relasi `public function user() { return $this->belongsTo(User::class, 'id_user'); }`.

### B. Spesifikasi Kontrak API untuk Integrasi Client (`marketplace-kampsewa-web`)
1. **Standarisasi Parameter `GET /api/transaksi/bank-toko`**:
   - Mendukung URL Query Parameter `?id_user={id_user}` maupun request payload.
   - Mendukung autentikasi `Authorization: Bearer <token>` (Sanctum) untuk otomatis mendeteksi pemilik toko saat parameter `id_user` tidak dikirimkan.
   - **Aturan Respon Aman**: Jika `id_user` dan `name_store` tidak dikirimkan atau bernilai null, respon wajib mengembalikan array kosong `{"message": "success", "bank": []}` tanpa membocorkan data rekening pengguna/toko lain.
2. **Endpoint Manajemen Rekening Toko (`UserController`)**:
   - `POST /api/user/tambah-bank`: Menambahkan data rekening bank baru untuk toko mitra.
   - `POST /api/user/update-bank/{id_bank}`: Memperbarui nomor rekening atau nama bank toko.
   - `GET /api/user/delete-bank/{id_bank}`: Menghapus rekening toko mitra terkait.

```php
        if ($id_user) {
            $query->where('id_user', $id_user);
        }
        if ($name_store) {
            $query->orWhere('name_store', $name_store); // ERROR: kolom name_store tidak ada di tabel bank
        }

    ->get();

// SESUDAH PERBAIKAN:
// 1. Mendukung pembacaan dari query param maupun request body
$id_user = request()->query('id_user') ?? request()->input('id_user');
$name_store = request()->query('name_store') ?? request()->input('name_store');

// 2. Fallback otomatis ke user login Bearer Sanctum

}

// 3. ISOLASI DATA KETAT: Jika tidak ada id_user dan tidak ada name_store, kembalikan array kosong!
if (!$id_user && !$name_store) {
    return response()->json([
        'message' => 'success',
        'bank' => [],
    ]);
}

// 4. Query presisi dengan relasi user untuk filter name_store
$bank = Bank::select('bank.id', 'bank.id_user', 'bank.rekening', DB::raw('UPPER(bank.bank) as bank'))
    ->where(function ($query) use ($id_user, $name_store) {

        }
```

  ```dart
  Get.back(

          'biayaAntar': tarifAntarToko,
  ```

- **Kirimkan Parameter ke `apiTransaksi.transaksiCheckout`**:
  Sertakan `opsi_pengiriman: opsiPengiriman`, `biaya_antar: biayaAntar`, dan `alamat_pengiriman: alamatPengiriman.value`.

## 1. Latar Belakang Masalah & Studi Kasus (Business Logic Rules)

Dalam pengelolaan program diskon katalog produk oleh mitra toko, ditemukan beberapa skenario tumpang tindih (*discount overlap / conflict*) yang harus dicegah agar tidak menimbulkan kebingungan sistem dan potensi manipulasi harga ganda (*double discounting*):

### Studi Kasus 1: Larangan Diskon Ganda pada Produk yang Sama (No Double Discounting)
- **Skenario**: Suatu produk (misal *Produk A*) telah diikutsertakan ke dalam program diskon aktif sebesar 10%.
- **Aturan**:
  - Mitra **TIDAK DAPAT** membuat program diskon baru lagi untuk *Produk A*.
  - Mitra **hanya diperbolehkan mengedit atau menghapus** program diskon yang sedang menaungi *Produk A* tersebut.
  - Penambahan data diskon baru hanya dapat dilakukan untuk produk-produk toko yang **belum memiliki diskon aktif** (*clean products*).

### Studi Kasus 2: Aturan Tunggal Diskon Toko Keseluruhan (Store-Wide Uniqueness)
- **Skenario**: Toko mitra mengaktifkan promo diskon untuk seluruh katalog toko (*All Products*).
- **Aturan**:
  - Dalam satu waktu aktif, satu toko mitra **HANYA BISA MEMILIKI MAKSIMAL 1 DISKON KESELURUHAN (`all_products`) YANG AKTIF**.
  - Mitra **TIDAK BISA** membuat diskon keseluruhan toko baru selama diskon keseluruhan sebelumnya masih berstatus aktif dan dalam masa berlaku.
  - Mitra baru dapat membuat diskon keseluruhan baru jika promo toko keseluruhan sebelumnya telah **kedaluwarsa (expired)**, **dinonaktifkan (inactive)**, atau **dihapus**.
  - Promo toko keseluruhan yang sedang aktif tentu dapat diedit atau dihapus sewaktu-waktu oleh mitra.

### Studi Kasus 3: Dua Opsi Penanganan Konflik Saat Memilih Diskon Seluruh Produk
- **Skenario**: Mitra ingin membuat diskon toko keseluruhan (*All Products*), namun di saat bersamaan terdapat beberapa produk toko yang sedang berstatus aktif dalam program diskon parsial (*Selected Products*).
- **Aturan (Sistem Menyediakan 2 Sub-Opsi)**:
  1. **Opsi 1: Samaratakan ke Seluruh Produk (Replace Diskon Lama)**:
     - Diskon baru ini disamaratakan ke seluruh katalog produk toko.
     - Diskon parsial lama pada produk-produk yang bersangkutan akan di-replace / dilepas (dinonaktifkan) sehingga seluruh produk mengikuti nilai diskon baru yang seragam.
  2. **Opsi 2: Pertahankan Diskon Lama (Skip / Lewati)**:
     - Produk-produk yang saat ini sudah memiliki promo diskon aktif dibiarkan tetap menggunakan diskon lamanya.
     - Diskon toko baru hanya diaplikasikan pada produk-produk toko lainnya yang belum memiliki diskon aktif.

## 9. Perbaikan Bug: SQL 1055 `only_full_group_by` pada Endpoint Riwayat Transaksi

### Penyebab Masalah (Root Cause):
Pada log server ditemukan error HTTP 500:
`SQLSTATE[42000]: Syntax error or access violation: 1055 Expression #21 of SELECT list is not in GROUP BY clause and contains nonaggregated column 'marketplacekampsewa.pembayaran_penyewaan.biaya_antar'`

Hal ini terjadi saat aplikasi mobile mengakses `GET /api/riwayat-transaksi` (method `riwayat` di `TransaksiController.php`). Penambahan kolom `biaya_antar`, `jenis_transaksi`, `opsi_pengiriman`, dan `alamat_pengiriman` pada klausa `SELECT` sebelumnya belum diikutsertakan pada klausa `GROUP BY`, sehingga MySQL strict mode (`sql_mode=only_full_group_by`) menolak query dan menghasilkan Server Error 500 ke aplikasi mobile.

### Solusi & Hasil Perbaikan:
Klausa `$query->groupBy(...)` pada [`app/Http/Controllers/Api/TransaksiController.php`](file:///D:/Projects/Marketplace%20KampSewa/marketplace-kampsewa-web/app/Http/Controllers/Api/TransaksiController.php#L499-L525) telah diselaraskan dengan menambahkan seluruh kolom non-agregat tersebut:
```php
'pembayaran_penyewaan.biaya_antar',
'pembayaran_penyewaan.jenis_transaksi',
'penyewaan.opsi_pengiriman',
'penyewaan.alamat_pengiriman',
```
Semua query riwayat transaksi pada tab *belum-bayar*, *pengambilan*, *berlangsung*, *selesai*, *dibatalkan*, dan *denda-belum-lunas* kini mengembalikan **HTTP 200 OK** secara konsisten.
