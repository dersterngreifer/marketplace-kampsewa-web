### 2. Rekomendasi & Ketentuan Khusus Untuk Team Frontend (Mobile & Web)

Mengingat konsep transaksi tetap menggunakan sistem **Manual (Transfer User-to-User)**, pihak frontend wajib memperhatikan beberapa poin penting berikut demi keamanan sistem:

#### A. Watermark Otomatis KTP (Telah Diimplementasikan di Backend)
Sebagai bentuk keamanan, foto jaminan sewa (KTP/Identitas) kini **otomatis diberikan Watermark** berupa teks transparan bertuliskan "HANYA UNTUK SEWA DI KAMPSEWA" saat diunggah.
*   **Lokasi Logika:** Fungsi `addWatermarkToImage` di dalam `TransaksiController.php`.
*   **Info Tim Frontend:** Anda tidak perlu lagi melakukan manipulasi *canvas* dari sisi *frontend* (mobile/web) karena sistem server sudah menanganinya menggunakan library bawaan PHP (GD Library). Pastikan saja tipe file yang dikirim valid (`.png` atau `.jpg`).

#### B. Alur Logika Transaksi di Frontend (2-Step Process)
Tim Frontend wajib membagi proses penyewaan menjadi **2 Tahap (Step)** berdasarkan struktur API:
1. **Tahap 1 (Checkout):** 
   - *Syarat:* Pastikan user sudah melengkapi `nomor_identitas` di profil akunnya (jika tidak, API `/checkout` akan memberikan response 403).
   - User memilih tanggal sewa, barang, dan hit API `/checkout`. (Catatan: *Stok barang akan langsung dipotong/di-lock oleh sistem saat ini*).
2. **Tahap 2 (Pembayaran & Upload KTP):**
   - Setelah checkout sukses, arahkan user ke halaman tagihan/pembayaran.
   - User diminta mentransfer dana ke rekening toko, kemudian mengunggah **2 foto**: Foto Bukti Pembayaran (`bukti_pembayaran`) dan Foto Jaminan Sewa/KTP (`jaminan_sewa`).
   - Frontend memanggil API `/pembayaran` (atau `/bayar-sekarang`) dengan tipe `multipart/form-data`.

#### C. Perbaikan UX / Proses Pembayaran
Saat melakukan *hit* ke endpoint `bayarSekarang` atau `pembayaran`, Frontend sebaiknya tidak memberikan kesan bahwa transaksi telah otomatis selesai. Frontend harus memberitahukan ke User: *"Bukti sedang diverifikasi oleh pihak toko, mohon tunggu beberapa saat."*
