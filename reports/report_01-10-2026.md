## Report 01-10-2026 - API Chat Antar Pengguna

**Telah Dilakukan:**
1. Membuat migration dan tabel baru untuk fitur Chat: `chat_rooms` dan `chat_messages`.
2. Membuat model Eloquent `ChatRoom` dan `ChatMessage` dengan relasi yang sesuai (user, messages, dll).
3. Membuat controller baru `ChatController` dengan implementasi endpoint untuk list chat, detail pesan dalam room/lawan bicara, kirim pesan, dan jumlah pesan yang belum dibaca (unread).
4. Menambahkan route API di `routes/api.php` di dalam middleware `auth:sanctum`.

**Daftar Endpoint API:**
Semua endpoint membutuhkan Header `Authorization: Bearer <token>` karena dibungkus oleh `auth:sanctum`.

### 1. Get List Chat Rooms (Inbox)
- **Endpoint**: `GET /api/chat/rooms`
- **Fungsi**: Mendapatkan daftar riwayat percakapan/room yang dimiliki oleh pengguna beserta info lawan bicara, pesan terakhir, dan badge pesan belum dibaca.
- **Contoh Response JSON**:
```json
{
    "success": true,
    "data": [
        {
            "room_id": 1,
            "last_message": "Apakah barang masih ready?",
            "updated_at": "2026-10-01T08:00:00.000000Z",
            "unread_count": 2,
            "user": {
                "id": 2,
                "name": "Budi Santoso",
                "foto_profile": "http://example.com/profile.jpg",
                "nama_toko": "Toko Budi"
            }
        }
    ]
}
```

### 2. Get Chat Messages By Room (Detail Percakapan)
- **Endpoint**: `GET /api/chat/room/{room_id}/messages`
- **Fungsi**: Mendapatkan daftar detail percakapan/pesan berdasarkan ID room. Pesan yang sebelumnya `is_read = false` akan otomatis diupdate menjadi `is_read = true` (telah dibaca).
- **Contoh Response JSON**:
```json
{
    "success": true,
    "data": [
        {
            "id": 1,
            "room_id": 1,
            "sender_id": 2,
            "receiver_id": 1,
            "message_text": "Iya barang masih ready kak.",
            "is_read": 1,
            "created_at": "2026-10-01T08:01:00.000000Z",
            "updated_at": "2026-10-01T08:05:00.000000Z"
        }
    ]
}
```

### 3. Get Chat Messages By User Lawan (Detail Percakapan)
- **Endpoint**: `GET /api/chat/messages/{user_id_lawan}`
- **Fungsi**: Alternatif untuk membuka chat langsung berdasarkan ID User lawan. Otomatis mengubah `is_read` menjadi `true`.
- **Contoh Response JSON**: (Format sama seperti di atas)

### 4. Send Message (Kirim Pesan)
- **Endpoint**: `POST /api/chat/send`
- **Body Request**:
```json
{
    "receiver_id": 2,
    "message": "Terima kasih infonya."
}
```
- **Fungsi**: Mengirim pesan ke pengguna lawan. Jika room chat belum ada, backend akan membuatkannya secara otomatis.
- **Contoh Response JSON**:
```json
{
    "success": true,
    "message": "Message sent",
    "data": {
        "id": 2,
        "room_id": 1,
        "sender_id": 1,
        "receiver_id": 2,
        "message_text": "Terima kasih infonya.",
        "is_read": false,
        "created_at": "2026-10-01T08:05:00.000000Z",
        "updated_at": "2026-10-01T08:05:00.000000Z"
    }
}
```

### 5. Unread Badges Summary (Total Pesan Belum Dibaca)
- **Endpoint**: `GET /api/chat/unread-summary`
- **Fungsi**: Mendapatkan total pesan masuk dari semua percakapan yang statusnya belum dibaca. (Dapat digunakan untuk badge Bottom Navigation).
- **Contoh Response JSON**:
```json
{
    "success": true,
    "data": {
        "total_unread_count": 5
    }
}
```

**Catatan untuk Frontend**:
- Sesuai dengan catatan, frontend bisa memisahkan list di "Semua" dan "Belum dibaca" dengan mengecek array response `unread_count > 0` dari endpoint `/api/chat/rooms`.
- Badge summary badge bisa diambil secara terpisah dari endpoint `/api/chat/unread-summary`.

## Update Report 01-10-2026 (Part 2) - Penyesuaian Status Read pada Chat Messages

**Telah Dilakukan:**
1. **Penyesuaian Response `is_read`**: Menambahkan `$casts = ['is_read' => 'integer'];` pada model `ChatMessage` agar response API untuk `GET Messages` secara konsisten mengembalikan nilai `0` atau `1` alih-alih boolean.
2. **Penambahan Field `is_read_last`**: Menambahkan logika pada endpoint `GET /api/chat/rooms` (ChatController) untuk mengambil history pesan terakhir dan menentukan nilai `is_read_last`. 

**Perubahan pada Endpoint `GET /api/chat/rooms`:**
Kini response memuat property tambahan `is_read_last` yang menandakan status read dari pesan terakhir (apabila pesan tersebut dikirim oleh *current user*).
- `is_read_last` = `1` (Sudah dibaca oleh lawan, atau pengirim terakhir bukan current user).
- `is_read_last` = `0` (Pesan dikirim oleh current user dan belum dibaca oleh lawan).

**Contoh Response JSON Baru untuk /rooms**:
```json
{
    "success": true,
    "data": [
        {
            "room_id": 1,
            "last_message": "Apakah barang masih ready?",
            "updated_at": "2026-10-01T08:00:00.000000Z",
            "unread_count": 2,
            "is_read_last": 0,
            "user": {
                "id": 2,
                "name": "Budi Santoso",
                "foto_profile": "http://example.com/profile.jpg",
                "nama_toko": "Toko Budi"
            }
        }
    ]
}
```

**Perubahan pada Endpoint GET Messages:**
Kini field `is_read` akan mutlak tampil sebagai tipe integer `0` (false) atau `1` (true).

**Contoh Response JSON Baru untuk /room/{id}/messages atau /messages/{user_id_lawan}**:
```json
{
    "success": true,
    "data": [
        {
            "id": 1,
            "room_id": 1,
            "sender_id": 2,
            "receiver_id": 1,
            "message_text": "Iya barang masih ready kak.",
            "is_read": 1,
            "created_at": "2026-10-01T08:01:00.000000Z",
            "updated_at": "2026-10-01T08:05:00.000000Z"
        }
    ]
}
```

## Update Report 01-10-2026 (Part 3) - Fitur Unread & Sorting Feedback Chat

**Telah Dilakukan:**
1. **Filter 'Belum Dibaca' (Unread)**: Menambahkan parameter `is_unread=1` atau `filter=belum_dibaca` pada endpoint `GET /api/chat-room` untuk memfilter dan menampilkan daftar sesi feedback chat yang memiliki unread message.
2. **Total Unread Count API**: Membuat endpoint baru `GET /api/chat-room/unread-count` untuk mengambil total jumlah keseluruhan pesan feedback yang belum dibaca.
3. **Sorting Tab 'Semua'**: Mengubah sistem sorting pada endpoint `GET /api/chat-room` agar data diurutkan berdasarkan `latest_message.created_at` secara DESC, sehingga chat dengan pesan terbaru akan selalu berada di posisi paling atas.
